EAGLE-J CONNECT — FINAL DEPLOYMENT CHECKLIST

A. SUPABASE
1. Open the existing Eagle-J Connect project in Supabase.
2. Export/back up your current database schema and data first.
3. Open SQL Editor and run SUPABASE-BASE-FINAL.sql only.
4. Wait for Success and review the verification rows returned at the end.
5. Do not run the older jobs/business/admin/profile SQL files afterward; they are superseded by the canonical migration.

B. GITHUB PAGES
1. Extract the ZIP.
2. Open eagle-j-connect-main.
3. Upload the CONTENTS of that folder to the root of the existing GitHub Pages repository (not the folder itself).
4. Commit the changes and wait for Pages to publish.
5. Open https://eagle-jconnect.github.io/eagle-j-connect/ and refresh the page.

C. TEST IN THIS ORDER
- Register a new account (email confirmation if enabled) and verify a profile is created.
- Sign in with email/password and sign out.
- Open the public member directory and verify only public active profiles appear.
- Create a job; verify it is pending and hidden publicly until an admin approves it.
- Create a business/listing; verify it is pending and hidden publicly until an admin approves it.
- Upload listing/profile images.
- Log in as the configured admin; approve/reject content, disable/reactivate a user, and test account deletion only with a test account.
- Test Google login only after Google OAuth is configured.

SECURITY NOTES
- Never place a service-role/secret key in frontend files.
- The migration grants administrator access to Judes Versanne's verified Auth UUID. Change that UUID if reusing the SQL for another project.
- Social network publishing still requires external OAuth credentials and Edge Function configuration; see SOCIAL-MEDIA-SETUP.md.
